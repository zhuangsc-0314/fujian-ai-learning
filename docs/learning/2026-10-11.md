## 1. 异常：从哪儿失败，就从哪儿跳出

```text
invoke抛出SDK异常
→ 跳过try内剩余语句，包括show_response
→ 寻找匹配的except
→ finally执行
```

不是assert让show_response跳过。测试断言在main返回后检查行为；例如assert_not_called检查show_response没有被调用，符合预期时不会抛AssertionError。

**先捕获具体子类，再捕获通用父类。** APITimeoutError属于APIConnectionError的子类；若连接分支放前面，超时会先被它捕获。AuthenticationError、RateLimitError等也应在APIStatusError兜底之前。

| 错误 | 该怎样理解和处理 |
| --- | --- |
| 401 / AuthenticationError | 认证失败；原样重复请求不会修复凭证。认证需要有效凭证；权限不足通常是403 |
| 429 / RateLimitError | 先判断频率/额度等限制原因；等待不一定解决。不能仅凭429断定模型繁忙 |
| 超时 | 客户端没在期限内取得结果；服务端可能已经执行。响应传输也可能失败，不能据此保证未收费 |
| 连接异常 | 检查网络/代理；不打印原始请求或凭证 |
| 500 / InternalServerError | 可由APIStatusError兜底显示安全HTTP提示；失败不伪装为成功 |

本课关闭自动重试。客户端“尝试1次”只说明程序到达调用位置，不能证明服务端执行/成功/收费。离线替换invoke时，客户端尝试可为1，实际网络请求仍为0。

## 2. patch：临时换一个零件

`patch`在with范围内替换对象属性，离开后恢复；`side_effect=异常对象`让被替换的方法被调用时抛异常。构造一个异常对象不等于抛出它。

1.3-C运行的是原1.2 main()，但模型构造器和invoke被替换；SDK异常是本地注入，不是DeepSeek实际HTTP失败。它验证外层except能接住错误，不证明SDK内部HTTP映射、供应商行为或计费。

## 3. token：用量、元数据和预算

1.2用户历史记录：**材料78字符，输入147 token、输出91、合计238，finish_reason为stop，耗时0.98秒。** 当时没有记录模型名/请求ID，不能从现在.env反推。

1. **token不等于字符。** 模型把文本切成处理单位；一个单位可能是字、词的一部分或符号。输入还包含系统约束、学习目标、材料和消息格式，所以78材料字符不等于输入147 token。
2. **usage_metadata记录用量**：input_tokens、output_tokens、total_tokens；**response_metadata描述响应**：例如finish_reason；**content是回答正文**。
3. **max_tokens=256是输出上限，不是费用预算。** 不一定生成满256；输入/输出单价、缓存等都影响金额。未核对价目与账单，不把token数写成费用。

你已独立完成的关键代码：

```python
print(f"合计token：{show_count(counts.get('total_tokens'))}")
```

`.get()`缺字段返回None；show_count将None显示为“未知”，将明确的0显示为“0”。不能用`value or '未知'`，因为0也是假值；不能用缺失值补0或认定免费。部分字段缺失时，也不要自行相加冒充上游给出的总数。

`stop`不证明内容事实正确；`length`提示可能截断，不自动重发。回答仍需对照原文，结构通过也不代表内容有据。
