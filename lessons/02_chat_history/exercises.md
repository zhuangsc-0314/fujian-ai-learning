# 第二课练习与 code review

先运行演示和交互模式，再做以下练习。每次模型调用都是真实 API 请求。

## 练习 1：观察消息序列

在 VS Code 中给 `history.extend(...)` 设置断点。记录第一轮完成、第二轮完成时消息列表的角色顺序。

预期数量分别是 2 和 4。先自己写出角色名称，再在调试器中检查。

## 练习 2：清空历史

进入 `--chat` 模式，先告诉模型你的名字，随后询问名字，再输入 `/clear` 后重复询问。

记录模型实际回答，并解释第二次询问提交的 history 为什么是空列表。不要把“猜对姓名”当成持久记忆的证明。

## 练习 3：改变当前问题

将演示第一轮的学习内容改为“Python”，第二轮问题保持不变。运行后检查模型是否使用了修改后的历史，而非返回写死的答案。

## 练习 4：模板变量

在 system 消息中增加 `{language}`，并在 `run_turn()` 构造的 inputs 中加入对应的键。

先预测只改模板、不改 inputs 时会发生什么，再验证。恢复可运行状态后，用另一种语言回答一次。

## 练习 5：限制为最近两轮（进阶）

在每轮保存成功之后，将 history 限制为最后 4 条消息。

要求保留 human/ai 成对消息，保持顺序，并修改原列表。对比下面两行的区别：

```python
history = history[-4:]
history[:] = history[-4:]
```

第一行在函数内重新绑定局部变量；第二行修改调用者持有的列表。不要把粗略的消息数量限制理解为精确的 token 控制。

## Review 检查题

1. MessagesPlaceholder 与普通字符串占位符有什么区别？
2. 为什么发送请求前不把当前 question 追加到 history？
3. 为什么同时保存 HumanMessage 和 AIMessage？
4. stream 的最后一个 chunk 是否包含整份回答？
5. 为什么 history 的修改能影响下一轮？
6. 本课退出后再次运行，为什么没有之前的记录？

<details>
<summary>完成后再看参考答案</summary>

1. MessagesPlaceholder 插入多条消息并保留角色；普通字符串变量只是单条消息文本的一部分。
2. 模板末尾已经包含本轮问题，提前追加会重复发送；本课只在成功后写入完整的一轮。
3. 两者共同表示完整对话，AI 回答可能包含下一轮要引用的内容。
4. 不一定；片段通常只包含部分内容或元数据，需要累加。
5. list 是可变对象，extend 修改的是调用者和函数共同持有的列表。
6. history 仅存在当前进程内存中，没有写入数据库或文件。
